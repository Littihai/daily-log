# Daily Log - ตารางงานประจำวัน

เว็บปฏิทินบันทึกงานรายวัน (มุมมอง วัน / 5 วัน / สัปดาห์ / เดือน) พร้อมรายงานสรุป
ล็อกอินด้วยรหัส 6 หลักอย่างเดียว (ไม่ต้องใส่ชื่อ ระบบรู้เองว่าเป็นใคร) แยกสิทธิ์ตามผู้ใช้ เก็บข้อมูลใน Firebase Firestore

- เว็บ: https://ritz-dailylog-3476.web.app
- ติดตั้งครั้งแรก: https://ritz-dailylog-3476.web.app/#setup
- Firebase Console: https://console.firebase.google.com/project/ritz-dailylog-3476

คู่มือสร้างระบบตั้งแต่ศูนย์ทีละขั้นตอน: [docs/BUILD-GUIDE.md](docs/BUILD-GUIDE.md)

## สิทธิ์ผู้ใช้

| สิทธิ์ | ลงงาน | เห็นงานของคนอื่น | จัดการผู้ใช้ |
|---|---|---|---|
| User | ได้ | ไม่ได้ (เห็นเฉพาะของตัวเอง) | ไม่ได้ |
| Admin | ได้ | เห็นทุกคน แต่แก้/ลบได้เฉพาะงานของตัวเอง | เพิ่ม รีเซ็ตรหัส ปิด/เปิดใช้งาน เปลี่ยนสิทธิ์ |
| Overview | ไม่ได้ (ดูอย่างเดียว) | เห็นทุกคน | ไม่ได้ |

สิทธิ์เหล่านี้บังคับที่ฝั่งเซิร์ฟเวอร์ด้วยกฎใน `firestore.rules` ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ

## ติดตั้งครั้งแรก (ทำครั้งเดียว)

1. เปิด `/#setup`
2. ใส่ "รหัสติดตั้ง" (ตั้งเองในไฟล์ `firestore.rules` บรรทัด `setupKey ==` แทนค่า `CHANGE_ME_SETUP_KEY` ก่อน deploy ครั้งแรก), ชื่อแอดมิน, รหัสแอดมิน 6 หลัก และรหัส Overview 6 หลัก (เว้นว่างได้ ต้องไม่ซ้ำกับรหัสแอดมิน)
3. เข้าสู่ระบบเป็นแอดมิน จะเห็นแถบ "โอนงานเดิมให้ฉัน" ถ้ามีงานที่ลงไว้ก่อนมีระบบล็อกอิน กดครั้งเดียวเพื่อให้งานเหล่านั้นเป็นของแอดมิน
4. ไปที่ ตั้งค่า > ผู้ใช้งาน > เพิ่มผู้ใช้ ใส่ชื่อที่แสดง เลือกสิทธิ์ และตั้งรหัส 6 หลัก (กด "สุ่มรหัส" เพื่อให้ระบบเลือกรหัสที่ยังไม่มีใครใช้) แล้วแจ้งรหัสให้เจ้าของ

หลังติดตั้งแล้ว หน้านี้ใช้ซ้ำไม่ได้ (กฎอนุญาตให้ทำครั้งเดียว) ถ้าต้องการให้ปลอดภัยยิ่งขึ้น ให้เปลี่ยนรหัสติดตั้งในกฎแล้ว deploy ใหม่

## การทำงานของบัญชี

- ล็อกอินด้วย Firebase Authentication แบบอีเมล/รหัสผ่าน โดยอีเมลเป็นอีเมลสังเคราะห์ `รหัสภายใน.เลขรุ่น@dailylog.example.com` และรหัสผ่านคือรหัส 6 หลัก (ไม่มีการส่งอีเมลจริง)
- ตอนล็อกอิน ระบบหาเจ้าของรหัสจากเอกสารใน collection `codes` (ชื่อเอกสารคือ SHA-256 ของรหัส) จึงบังคับให้ **รหัสของแต่ละคนต้องไม่ซ้ำกัน**
- ผู้ใช้เปลี่ยนรหัสเองได้ที่ ตั้งค่า > เปลี่ยนรหัส (ระบบเช็กว่าไม่ซ้ำกับคนอื่น)
- ลืมรหัส: แอดมินกด "รีเซ็ตรหัส" ที่ผู้ใช้คนนั้น (ระบบสร้างบัญชีล็อกอินรุ่นใหม่ให้ งานเดิมยังอยู่ครบ เพราะงานผูกกับชื่อผู้ใช้)
- ปิดใช้งาน: ผู้ใช้เข้าระบบและอ่านข้อมูลไม่ได้ทันที ข้อมูลเดิมยังอยู่
- รหัส 6 หลักเดาง่าย และเมื่อไม่มีชื่อผู้ใช้ ใครก็ลองสุ่มรหัสเพื่อหาว่ารหัสไหนมีผู้ใช้ได้ ความเสี่ยงสูงกับสิทธิ์ที่เห็นข้อมูลทุกคน (Admin/Overview) จึงไม่ควรใช้เลขง่ายๆ เช่น 000111 ถ้าต้องการปลอดภัยขึ้น ให้เพิ่มความยาวรหัสหรือกลับไปใช้ชื่อผู้ใช้ + รหัส

## เชื่อม Outlook / Teams (Microsoft Graph)

ดึงนัดหมายและประชุม Teams ของคนที่ล็อกอินมาแสดงซ้อนในปฏิทิน (แถบลายเฉียง ม่วง = Teams, น้ำเงิน = Outlook) คลิกที่แถบเพื่อ "นำเข้าเป็นงาน" หรือเปิดลิงก์ประชุม
ปุ่ม Outlook บนแถบเครื่องมือเปิดหน้าต่างเทียบ: จำนวนนัด ชั่วโมงประชุม เทียบกับงานหมวดประชุมที่ลงไว้ และนำเข้าทีเดียวทั้งช่วงที่เห็น
อ่านปฏิทินของตัวเองอย่างเดียว (สิทธิ์ `Calendars.Read`) ไม่แก้ ไม่ส่งอีเมล ไม่เก็บนัดหมายลงฐานข้อมูล ไม่ดึงแชต ข้อความ หรือรายชื่อผู้เข้าร่วมจริง
นัดที่ยกเลิก ปฏิเสธ หรือเป็นนัดทั้งวันจะไม่แสดง นัดส่วนตัวแสดงเป็น "(นัดส่วนตัว)" โดยไม่โชว์หัวข้อ

### ลงทะเบียนแอป (ทำครั้งเดียว โดยผู้ดูแล Microsoft 365 ของบริษัท)

1. เปิด https://entra.microsoft.com > Applications > App registrations > New registration
2. ชื่อ `Daily Log` เลือก "Accounts in this organizational directory only" ใส่ Redirect URI ชนิด **Single-page application (SPA)** เป็น `https://ritz-dailylog-3476.web.app/redirect.html` (ถ้าจะลองในเครื่อง เพิ่ม `http://localhost:5173/redirect.html` ด้วย) แล้วกด Register
3. API permissions > Add a permission > Microsoft Graph > Delegated permissions > `Calendars.Read` (ถ้าบริษัทไม่ให้ผู้ใช้อนุมัติเอง กด "Grant admin consent" ให้ทั้งองค์กร)
4. หน้า Overview คัดลอก **Application (client) ID** และ **Directory (tenant) ID** ไปใส่ใน `public/ms-config.js` แล้ว deploy เว็บ (ค่าสองตัวนี้ไม่ใช่ความลับ ห้ามสร้าง client secret ไม่จำเป็น)
5. ผู้ใช้แต่ละคนไปที่ ตั้งค่า > เชื่อมต่อ Outlook / Teams แล้วล็อกอิน Microsoft

โทเคนของ Microsoft เก็บในเบราว์เซอร์ของผู้ใช้ และถูกล้างทุกครั้งที่ออกจากระบบ Daily Log
ลองหน้าตาโดยไม่ต้องมีบัญชีจริงได้ที่ `http://localhost:5173/?msmock` (ข้อมูลตัวอย่าง ใช้ได้เฉพาะ localhost)

## แอป Windows (.exe)

ไฟล์ `desktop/dist/DailyLog-1.0.0.exe` เป็นไฟล์เดียว ดับเบิลคลิกใช้ได้เลย ไม่ต้องติดตั้ง ไม่ต้องมีสิทธิ์แอดมิน (เปิดครั้งแรกใช้เวลาประมาณครึ่งนาทีเพราะแตกไฟล์ ครั้งต่อไปเร็วขึ้น)
แอปคือหน้าต่างที่เปิดเว็บจริง `ritz-dailylog-3476.web.app` ดังนั้นแก้เว็บแล้ว deploy แอปจะได้ของใหม่ทันที ไม่ต้องแจกไฟล์ใหม่ และใช้ล็อกอินกับการเชื่อม Outlook / Teams ได้เหมือนบนเว็บ

- ต้องต่ออินเทอร์เน็ต ถ้าไม่มีสัญญาณจะขึ้นหน้าแจ้งและลองใหม่เองเมื่อกลับมาออนไลน์
- ลิงก์ภายนอกเปิดในเบราว์เซอร์ปกติ ส่วนหน้าล็อกอิน Microsoft เปิดเป็นหน้าต่างเล็กในแอป
- ทางลัด: F5 หรือ Ctrl+R โหลดใหม่, F11 เต็มจอ, Ctrl + / - / 0 ซูม
- ครั้งแรกที่เปิดบนเครื่องใหม่ Windows อาจขึ้น "Windows protected your PC" เพราะไฟล์ยังไม่ได้ลงลายเซ็นดิจิทัล ให้กด More info แล้ว Run anyway (ลายเซ็นต้องซื้อใบรับรองจากผู้ออก)
- ข้อมูลล็อกอินที่จดจำไว้เก็บในโฟลเดอร์ผู้ใช้ของเครื่องนั้น กด "ออกจากระบบ" ในแอปก่อนส่งเครื่องต่อให้คนอื่น

สร้างไฟล์ใหม่ (ต้องมี Node.js) เฉพาะเมื่อแก้ตัวแอป เช่น เปลี่ยนที่อยู่เว็บหรือไอคอน ใน `desktop/main.js`:

```bash
cd desktop
npm install
node node_modules/electron/install.js
npm run build
```

โฟลเดอร์ `desktop/node_modules` และ `desktop/dist/win-unpacked` ลบทิ้งได้เมื่อไม่ใช้ ไม่กระทบไฟล์ .exe

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `public/index.html`, `styles.css`, `app.js` | ตัวเว็บแอป (ไม่มี build step) |
| `public/firebase-config.js` | ค่าเชื่อมต่อ Firebase (ถ้า projectId ว่าง จะเป็นโหมดทดลองในเครื่อง ไม่มีล็อกอิน ใช้ `?role=user\|admin\|overview` ลองหน้าตาแต่ละสิทธิ์) |
| `firestore.rules` | กฎความปลอดภัย: สิทธิ์ผู้ใช้ ความเป็นเจ้าของงาน และตรวจรูปแบบข้อมูล |
| `public/ms-config.js`, `redirect.html` | ค่า Client ID/Tenant ID ของแอป Microsoft และหน้ารับผลล็อกอิน |
| `desktop/` | ต้นทางแอป Windows (Electron) ไฟล์ .exe อยู่ใน `desktop/dist` |
| `firebase.json`, `.firebaserc` | ตั้งค่า Hosting, Firestore, การเปิดล็อกอินแบบอีเมล/รหัสผ่าน และ emulator |

## ทดสอบในเครื่อง (ไม่แตะข้อมูลจริง)

ต้องมี Java (สำหรับ Firestore emulator)

```bash
npx firebase-tools emulators:start --only auth,firestore --project ritz-dailylog-3476
python -m http.server 5173 --directory public
```

เปิด http://localhost:5173/?emu#setup (ต่อท้าย `?emu` เฉพาะ localhost เพื่อใช้ emulator แทนของจริง) แล้วติดตั้งครั้งแรกด้วยรหัสติดตั้งจากไฟล์กฎ

## Deploy

ถ้าแก้ `firestore.rules` ให้ deploy กฎก่อนเสมอ แล้วค่อย deploy เว็บ

```bash
npx firebase-tools deploy --only firestore:rules
npx firebase-tools deploy --only hosting
```

## ปรับหมวดงาน / สถานะ / ฟิลด์

- หมวดและสถานะ: แก้ `CATEGORIES` และ `STATUSES` ที่ต้นไฟล์ `public/app.js` ถ้าเพิ่มสถานะใหม่ต้องเพิ่มใน `d.status in [...]` ของ `firestore.rules` ด้วย
- ฟิลด์ใหม่: เพิ่มใน `FIELDS` ของ `app.js` และใน `hasOnly([...])` ของ `validEvent` ฟิลด์ใหม่ควรเป็นแบบไม่บังคับ เพื่อให้ข้อมูลเดิมยังใช้ได้
