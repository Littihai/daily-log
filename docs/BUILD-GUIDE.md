# คู่มือสร้าง Daily Log ทีละขั้นตอน

คู่มือนี้บอกทุกขั้นตอนที่ใช้สร้างระบบ Daily Log ตั้งแต่ต้น ใช้ได้สองแบบ

- **ทำซ้ำเป็นระบบใหม่** ทำตามทีละหัวข้อตั้งแต่ข้อ 1 ถึงข้อ 11
- **ทำความเข้าใจระบบที่มีอยู่** อ่านข้อ 0 แล้วข้ามไปหัวข้อที่สนใจ แต่ละหัวข้อบอกว่าไฟล์ไหนทำหน้าที่อะไร

ถ้าแค่อยากติดตั้งระบบที่มีอยู่ใน repo นี้ ให้ข้ามไปข้อ 11 แล้วทำตาม [README.md](../README.md)

---

## 0. ภาพรวมของระบบ

Daily Log คือเว็บปฏิทินบันทึกงานประจำวัน ผู้ใช้ล็อกอินด้วยรหัส 6 หลัก ผู้จัดการดูรายงานสรุปได้ มีแอป Windows และเชื่อมนัดหมาย Outlook / Teams ได้

| ส่วน | เทคโนโลยี | ไฟล์หลัก |
|---|---|---|
| หน้าเว็บ | HTML + CSS + JavaScript ล้วน ไม่มีขั้นตอน build | `public/index.html`, `styles.css`, `app.js` |
| ฐานข้อมูล | Firebase Firestore | `firestore.rules`, `firestore.indexes.json` |
| ล็อกอิน | Firebase Authentication (อีเมล/รหัสผ่าน) | `firestore.rules`, ส่วนล็อกอินใน `app.js` |
| โฮสติ้ง | Firebase Hosting | `firebase.json`, `.firebaserc` |
| ปฏิทิน Outlook / Teams | Microsoft Graph + MSAL.js | `public/ms-config.js`, `redirect.html` |
| แอป Windows | Electron | `desktop/` |
| ทดสอบกฎความปลอดภัย | Firebase Emulator + Python | `tests/rules_attack.py` |

ไลบรารีจากภายนอกทั้งหมดโหลดผ่าน CDN โดยระบุเวอร์ชันตายตัว จึงไม่ต้องมี `npm install` สำหรับตัวเว็บ

- Firebase SDK 10.14.1 จาก `gstatic.com`
- ExcelJS 4.4.0 จาก `cdn.jsdelivr.net` (โหลดเมื่อกดปุ่ม Excel)
- MSAL 3.28.1 จาก `cdn.jsdelivr.net` (โหลดเมื่อเชื่อม Outlook)

## 1. เตรียมเครื่อง

1. ติดตั้ง **Node.js** (เวอร์ชัน 20 ขึ้นไป) จาก https://nodejs.org แล้วตรวจสอบ
   ```bash
   node -v
   npm -v
   ```
2. ติดตั้ง **Git** จาก https://git-scm.com
3. ติดตั้ง **GitHub CLI** (`gh`) จาก https://cli.github.com ถ้าจะ push ขึ้น GitHub
4. ติดตั้ง **Java** (JDK 17 ขึ้นไป) ถ้าจะทดสอบกฎด้วย emulator
5. ติดตั้ง **Python 3** ถ้าจะรันชุดทดสอบ
6. ไม่ต้องติดตั้ง Firebase CLI ถาวร ใช้ผ่าน `npx firebase-tools ...` ได้เลย
7. ล็อกอิน Firebase ด้วยบัญชี Google ที่จะเป็นเจ้าของโปรเจกต์
   ```bash
   npx firebase-tools login
   ```
   เบราว์เซอร์จะเปิดให้อนุญาต ห้ามส่งไฟล์โทเคนที่ CLI เก็บในเครื่องให้ใคร

## 3. สร้างโปรเจกต์ Firebase และเว็บแอป

1. เลือกชื่อโปรเจกต์ที่ไม่ซ้ำใครทั้งโลก เช่น `ritz-dailylog-3476` แล้วสร้าง
   ```bash
   npx firebase-tools projects:create ritz-dailylog-3476 --display-name "Daily Log"
   ```
   ควรสร้างโปรเจกต์ใหม่เฉพาะระบบนี้ เพราะกฎ Firestore ใช้ร่วมกันทั้งโปรเจกต์ ถ้าใช้โปรเจกต์เดิมที่มีแอปอื่น กฎของเราจะไปทับของเขา
2. ผูกโฟลเดอร์กับโปรเจกต์ สร้างไฟล์ `.firebaserc`
   ```json
   { "projects": { "default": "ritz-dailylog-3476" } }
   ```
3. สร้างเว็บแอปในโปรเจกต์ แล้วดูค่าเชื่อมต่อ
   ```bash
   npx firebase-tools apps:create WEB "Daily Log" --project ritz-dailylog-3476
   npx firebase-tools apps:sdkconfig WEB <appId ที่ได้จากคำสั่งก่อนหน้า> --project ritz-dailylog-3476
   ```
4. สร้างไฟล์ `public/firebase-config.js` ใส่ค่าที่ได้
   ```js
   export const firebaseConfig = {
     apiKey: "...", authDomain: "...", projectId: "...",
     storageBucket: "...", messagingSenderId: "...", appId: "..."
   };
   ```
   ค่านี้ไม่ใช่ความลับ เป็นตัวระบุเว็บแอปสาธารณะ ความปลอดภัยจริงอยู่ที่ `firestore.rules` ถ้า `projectId` เป็นค่าว่าง แอปจะเข้า "โหมดทดลอง" เก็บข้อมูลในเบราว์เซอร์และไม่มีล็อกอิน เหมาะกับการลองหน้าตา

## 4. ตั้งค่า Firebase Hosting และฐานข้อมูล

1. สร้าง `firebase.json`
   ```json
   {
     "hosting": {
       "public": "public",
       "ignore": ["firebase.json", "**/.*", "**/node_modules/**"],
       "headers": [
         { "source": "**/*.@(js|css|html)", "headers": [{ "key": "Cache-Control", "value": "no-cache" }] }
       ]
     },
     "firestore": { "rules": "firestore.rules", "indexes": "firestore.indexes.json" },
     "auth": { "providers": { "emailPassword": true } },
     "emulators": {
       "auth": { "port": 9099, "host": "127.0.0.1" },
       "firestore": { "port": 8080, "host": "127.0.0.1" },
       "ui": { "enabled": false },
       "singleProjectMode": true
     }
   }
   ```
   ส่วน `headers` บอกเบราว์เซอร์ให้ตรวจไฟล์ใหม่ทุกครั้ง จึงเห็นของใหม่ทันทีหลัง deploy
2. สร้างฐานข้อมูลและ deploy กฎ (ใช้กฎจากข้อ 7 ที่เขียนเสร็จแล้ว หรือกฎชั่วคราวที่ปฏิเสธทุกอย่างก่อนก็ได้)
   ```bash
   npx firebase-tools deploy --only firestore:rules
   ```
   คำสั่งนี้เปิด API ของ Firestore และสร้างฐานข้อมูลให้ ถ้าขึ้น 403 ให้รอสักครู่แล้วรันใหม่ หรือกด Create database ใน Firebase Console แทน
3. deploy เว็บ
   ```bash
   npx firebase-tools deploy --only hosting
   ```
   เว็บจะอยู่ที่ `https://<project-id>.web.app`

## 5. สร้างเว็บแอปปฏิทิน

เขียนเป็นไฟล์เดียวต่อชนิด ไม่ใช้เฟรมเวิร์ก ลำดับที่สร้างมีดังนี้

### 5.1 โครงหน้า (`public/index.html`)

1. ส่วนหัวโหลดฟอนต์ Inter และ Noto Sans Thai จาก Google Fonts
2. แถบข้างซ้าย: โลโก้ ช่องค้นหา เมนู การ์ดงานถัดไป การ์ดสรุปวันนี้ สถานะการเชื่อมต่อ
3. พื้นที่หลัก: แถบเครื่องมือ (วันนี้ ลูกศร ชื่อเดือน ปุ่ม D 5D W M ปุ่มเพิ่มงาน) และพื้นที่ปฏิทิน
4. หน้าต่างฟอร์มเพิ่ม/แก้ไขงาน (`<dialog>`) และเมนูคลิกขวา

### 5.2 หน้าตา (`public/styles.css`)

1. กำหนดค่าสีและขนาดเป็นตัวแปร CSS ที่ `:root`
2. ตารางเวลา: 24 ชั่วโมง ชั่วโมงละ 72 พิกเซล หัวตารางและแถบเวลาค้างติดขอบตอนเลื่อน
3. การ์ดงาน: พื้นสีอ่อน แถบสีด้านซ้ายตามหมวดงาน
4. มุมมองเดือน ฟอร์ม หน้ารายงาน
5. จอแคบ (ไม่เกิน 960 พิกเซล) ซ่อนแถบข้างเป็นแถบบน
6. กฎสำหรับพิมพ์ ซ่อนแถบข้างและปุ่มต่างๆ

### 5.3 ตรรกะ (`public/app.js`)

ลำดับส่วนในไฟล์

1. **ค่าคงที่** หมวดงาน (`CATEGORIES`) สถานะ (`STATUSES`) ชื่อวันและเดือนภาษาไทย ปีพุทธศักราช
2. **ฟังก์ชันช่วย** แปลงวันที่เป็นข้อความ คำนวณสัปดาห์เริ่มวันจันทร์ ป้องกันอักขระพิเศษ (`esc`)
3. **ชั้นเก็บข้อมูล** `localStore` สำหรับโหมดทดลอง และ Firestore สำหรับของจริง ทั้งสองมีฟังก์ชันชุดเดียวกัน (`subscribe`, `save`, `saveMany`, `remove`)
4. **ปฏิทิน** คำนวณตำแหน่งการ์ด จัดการ์ดที่ทับเวลากันให้อยู่คนละคอลัมน์ (`layoutDay`) เส้นเวลาปัจจุบัน
5. **ฟอร์มงาน** ตรวจข้อมูล ทำซ้ำรายวัน/รายสัปดาห์ (สร้างเป็นรายการแยกของแต่ละวัน)
6. **รายงานสรุป** ชั่วโมงตามหมวดและโปรเจกต์ รายละเอียดรายวัน พิมพ์ CSV ที่กันสูตรแฝง
7. **เริ่มทำงาน** `start()` ตัดสินใจใช้โหมดทดลองหรือเชื่อม Firebase

โครงสร้างข้อมูลของงาน หนึ่งงานคือหนึ่งเอกสารในคอลเลกชัน `events`

| ฟิลด์ | ชนิด | ความหมาย |
|---|---|---|
| `title`, `date`, `start`, `end` | ข้อความ | หัวข้อ วันที่ (`YYYY-MM-DD`) เวลา (`HH:MM`) |
| `category`, `status`, `project`, `note` | ข้อความ | หมวดงาน สถานะ โปรเจกต์ รายละเอียด |
| `assignee`, `link` | ข้อความ (ไม่บังคับ) | ผู้ทำ ลิงก์ (ต้องขึ้นต้น http หรือ https) |
| `ownerId`, `ownerName` | ข้อความ | เจ้าของงาน (ดูข้อ 7) |
| `createdAt`, `updatedAt` | เวลา | เวลาจากเซิร์ฟเวอร์ |

### 5.4 ลองในเครื่อง

```bash
python -m http.server 5173 --directory public
```

เปิด http://localhost:5173 ถ้าตั้ง `projectId` เป็นค่าว่างใน `firebase-config.js` จะเป็นโหมดทดลอง ใช้ `?role=user`, `?role=admin` หรือ `?role=overview` เพื่อลองหน้าตาของแต่ละสิทธิ์

## 6. ฟีเจอร์ที่เพิ่มภายหลัง

เพิ่มเข้า `app.js` ทีละอย่าง แต่ละอย่างทำอย่างไร

1. **ลากย้ายและยืดการ์ด** ใช้ pointer events (`pointerdown`, `pointermove`, `pointerup`) ปัดเวลาเป็นช่วง 15 นาที เลื่อนหน้าอัตโนมัติเมื่อลากใกล้ขอบ กด Esc ยกเลิก บนมือถือใช้ได้เฉพาะลากขอบล่างเพื่อยืดเวลา เพราะการลากด้วยนิ้วชนกับการเลื่อนหน้า
2. **ลากคลุมช่องว่างเพื่อสร้างงาน** แสดงกรอบประ แล้วเปิดฟอร์มพร้อมช่วงเวลา
3. **เลิกทำ** ทุกการลบ ย้าย ปรับเวลา เลื่อนงานค้าง เก็บสำเนาของเดิมไว้ในปุ่มบนแจ้งเตือน ลบแล้วสร้างกลับด้วยรหัสเอกสารเดิม
4. **ตัวกรอง** หมวด สถานะ โปรเจกต์ ผู้ทำ ใช้ทั้งปฏิทินและรายงาน
5. **เทมเพลตงาน** มีค่าเริ่มต้น 4 แบบ และเก็บของตัวเองในเบราว์เซอร์ (`localStorage`)
6. **เตือนเวลาซ้อน** ตรวจก่อนบันทึก ให้กดบันทึกซ้ำเพื่อยืนยัน
7. **หน้างานค้าง** งานก่อนวันนี้ที่ยังไม่เสร็จ เลื่อนมาวันนี้ได้
8. **รายงาน** สัปดาห์ เดือน ช่วงวันที่เอง เทียบกับช่วงก่อนหน้า
9. **ส่งออก Excel** โหลด ExcelJS ตอนกดปุ่ม สร้าง 3 ชีต (รายการ สรุปรายวัน สรุปตามหมวด) ใช้สูตร `SUMIFS`/`COUNTIFS` อ้างอิงชีตรายการ แก้ข้อมูลแล้วสรุปอัปเดตตาม
10. **สำรองและนำเข้า** สำรองเป็น JSON นำเข้าแล้วข้ามรายการซ้ำและตัดลิงก์ที่ไม่ใช่ http
11. **โหมดมืด** ใช้ตัวแปรสี `[data-theme="dark"]` ตั้งค่าตั้งแต่ส่วนหัวของหน้าเพื่อไม่ให้กะพริบ
12. **เพิ่มไว้หน้าจอหลักมือถือ** `manifest.webmanifest` และไอคอน 192 กับ 512 พิกเซล

## 7. ระบบล็อกอินและสิทธิ์

### 7.1 แนวคิด

- ต้องการให้ล็อกอินด้วยรหัส 6 หลักอย่างเดียว และรหัสของแต่ละคนไม่ซ้ำกัน
- สิทธิ์แยกเป็น User (เห็นและแก้เฉพาะงานตัวเอง) Admin (จัดการผู้ใช้ เห็นงานทุกคน แก้ได้เฉพาะของตัวเอง) Overview (เห็นงานทุกคน ดูอย่างเดียว)
- การแยกสิทธิ์ต้องบังคับที่ฝั่งเซิร์ฟเวอร์ด้วยกฎ Firestore ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ

### 7.2 เปิดล็อกอินแบบอีเมล/รหัสผ่าน

ใส่ส่วน `auth` ไว้ใน `firebase.json` แล้วรัน

```bash
npx firebase-tools deploy --only auth
```

(หรือเปิดเองใน Firebase Console ที่ Authentication > Sign-in method > Email/Password)

### 7.3 โมเดลข้อมูล

Firebase Authentication ต้องมีอีเมลกับรหัสผ่าน จึงใช้อีเมลสังเคราะห์ที่ไม่มีการส่งอีเมลจริง

- **บัญชีล็อกอิน** อีเมล `รหัสภายใน.เลขรุ่น@dailylog.example.com` รหัสผ่านคือรหัส 6 หลัก (เลขรุ่นเพิ่มเมื่อแอดมินรีเซ็ตรหัส เพราะฝั่งเบราว์เซอร์เปลี่ยนรหัสของคนอื่นโดยตรงไม่ได้)
- **`users/{รหัสภายใน}`** ข้อมูลผู้ใช้: ชื่อที่แสดง สิทธิ์ (`user`, `admin`, `overview`) สถานะใช้งาน และอีเมลล็อกอินปัจจุบัน (`authEmail`)
- **`codes/{SHA-256 ของรหัส}`** เอกสารค้นหา ชี้จากรหัสไปหาบัญชีของเจ้าของ ตอนล็อกอินเว็บคำนวณค่าแฮชของรหัสที่พิมพ์ แล้วอ่านเอกสารนี้เพื่อรู้ว่าเป็นใคร เอกสารสร้างแล้วแก้ไม่ได้ จึงรับประกันว่ารหัสไม่ซ้ำ
- **`events/*`** เพิ่มฟิลด์ `ownerId` และ `ownerName` เพื่อบอกเจ้าของงาน
- **`config/setup`** เอกสารที่สร้างได้ครั้งเดียวตอนติดตั้งครั้งแรก

### 7.4 กฎ Firestore (`firestore.rules`)

1. ฟังก์ชันช่วย: `uname()` ตัดรหัสภายในจากอีเมลของผู้ล็อกอิน, `active()` ตรวจว่ามีเอกสารผู้ใช้ เปิดใช้งาน และอีเมลตรงกับ `authEmail` (กันคนแอบสมัครอีเมลคล้ายกัน), `isAdmin()`, `canLog()`, `canViewAll()`
2. `events` อ่านได้เมื่อเป็น Admin/Overview หรือเป็นเจ้าของ สร้างได้เมื่อระบุตัวเองเป็นเจ้าของ แก้และลบได้เฉพาะเจ้าของ Admin ยังรับโอนงานที่ไม่มีเจ้าของได้
3. `users` อ่านได้เฉพาะ Admin กับเจ้าของเอกสารเอง แก้ได้เฉพาะ Admin แต่ห้ามลดสิทธิ์หรือปิดใช้งานตัวเอง ห้ามลบ
4. `codes` อ่านได้ทีละเอกสาร (สำหรับล็อกอิน) ห้ามแก้ ลบได้เฉพาะ Admin หรือเจ้าของ
5. `config/setup` สร้างได้ครั้งเดียวและต้องใส่รหัสติดตั้งถูกต้อง
6. ทุกอย่างอื่นปฏิเสธทั้งหมด

ก่อน deploy ครั้งแรก แทนค่า `CHANGE_ME_SETUP_KEY` ในไฟล์ด้วยรหัสติดตั้งที่สุ่มเอง (ตัวอักษรและตัวเลขประมาณ 12 ตัว) เก็บไว้เป็นความลับ

### 7.5 ฝั่งหน้าเว็บ

1. หน้า Login: ช่องรหัส 6 หลัก (ฟังก์ชัน `buildOtp`) และปุ่มยืนยัน ไม่มีช่องชื่อ
2. ล็อกอิน: หา `codes/{แฮช}` แล้วเรียก `signInWithEmailAndPassword` ด้วยอีเมลที่ได้ จากนั้นอ่านเอกสารผู้ใช้เพื่อเอาสิทธิ์และชื่อ ถ้าถูกปิดใช้งานให้ออกจากระบบทันที
3. ผู้ใช้สิทธิ์ User ดึงงานด้วยคำสั่งกรอง `ownerId == ตัวเอง` เท่านั้น (กฎบังคับด้วย) Admin/Overview ดึงทั้งคอลเลกชัน
4. ซ่อนสิ่งที่สิทธิ์นั้นทำไม่ได้ เช่น ปุ่มเพิ่มงานของ Overview แต่ย้ำว่านี่เป็นแค่ความสะดวก ความปลอดภัยจริงอยู่ที่กฎ
5. ใช้แคชในหน่วยความจำเท่านั้น ไม่เก็บข้อมูลค้างในเครื่องที่ใช้ร่วมกัน

### 7.6 ติดตั้งครั้งแรก

1. deploy กฎและเว็บ (ข้อ 11)
2. เปิด `https://<project-id>.web.app/#setup`
3. ใส่รหัสติดตั้ง ชื่อแอดมิน รหัสแอดมิน 6 หลักสองครั้ง และรหัส Overview (ไม่บังคับ ต้องไม่ซ้ำกับรหัสแอดมิน)
4. ระบบสร้างบัญชีแอดมิน บันทึก `config/setup` และเอกสารผู้ใช้ แล้วสร้างผู้ใช้ Overview ให้
5. หลังติดตั้ง หน้านี้ใช้ซ้ำไม่ได้ เพราะ `config/setup` มีอยู่แล้วและแก้ไม่ได้

### 7.7 หลังติดตั้ง

1. เข้าเป็นแอดมิน ถ้ามีแถบ "พบงานเดิม" กด "โอนให้ฉัน" เพื่อรับงานที่ลงไว้ก่อนมีระบบล็อกอิน (ทำเป็นชุดเดียว ถ้ามีงานใดข้อมูลไม่ถูกรูปแบบ ทั้งชุดจะไม่ผ่าน)
2. ตั้งค่า > เพิ่มผู้ใช้ ใส่ชื่อ เลือกสิทธิ์ ตั้งรหัสหรือกด "สุ่มรหัส" ระบบตรวจว่าไม่ซ้ำ
3. รีเซ็ตรหัส: ระบบสร้างบัญชีล็อกอินรุ่นใหม่ให้ งานเดิมอยู่ครบเพราะงานผูกกับรหัสภายใน ไม่ผูกกับบัญชีล็อกอิน
4. ปิดใช้งาน: ผู้ใช้เข้าและอ่านข้อมูลไม่ได้ทันที ข้อมูลเดิมอยู่ครบ
5. ผู้ใช้เปลี่ยนรหัสตัวเองที่ ตั้งค่า > เปลี่ยนรหัส
6. แนะนำให้มีแอดมินสำรองอีกหนึ่งคน เพราะถ้าแอดมินคนเดียวลืมรหัส ไม่มีทางกู้ในหน้าเว็บ

## 8. ทดสอบกฎด้วย emulator

ทดสอบกับ emulator เพื่อไม่แตะข้อมูลจริง

1. เริ่ม emulator (ต้องมี Java) ในหน้าต่างเทอร์มินัลแรก
   ```bash
   npx firebase-tools emulators:start --only auth,firestore --project <project-id>
   ```
2. รันชุดทดสอบในหน้าต่างที่สอง
   ```bash
   python tests/rules_attack.py
   ```
   สคริปต์สร้างผู้ใช้ทดสอบ 5 คน (admin, overview, สอง User, และคนที่ถูกปิดใช้งาน) แล้วลองโจมตีกฎ 85 รายการ เช่น User อ่านหรือแก้งานคนอื่น เขียนทับรหัสของคนอื่น คนนอกสมัครบัญชีเอง ผู้ใช้ที่ถูกปิดใช้งาน ผลที่ถูกต้องคือ `85/85 passed` ถ้ามีข้อใดผิดจะแสดง FAIL
3. ลองทั้งระบบผ่านหน้าเว็บกับ emulator ได้ โดยเปิด `http://localhost:5173/?emu#setup` (ต่อท้าย `?emu` ใช้ได้เฉพาะ localhost) รหัสติดตั้งคือค่า `CHANGE_ME_SETUP_KEY` ในไฟล์กฎ
4. เมื่อแก้กฎ ให้รันชุดทดสอบนี้ซ้ำทุกครั้งก่อน deploy

## 9. เชื่อม Outlook / Teams

ประชุม Teams ที่นัดล่วงหน้าอยู่ในปฏิทิน Outlook จึงดึงผ่าน Microsoft Graph ตัวเดียว ใช้ MSAL.js ล็อกอินจากหน้าเว็บ ไม่ต้องมีเซิร์ฟเวอร์ ขอสิทธิ์อ่านปฏิทินของตัวเองอย่างเดียว (`Calendars.Read`)

### 9.1 ลงทะเบียนแอปใน Microsoft Entra (โดยผู้ดูแล Microsoft 365)

1. เปิด https://entra.microsoft.com แล้วเลือก Entra ID > App registrations > New registration
2. ชื่อ `Daily Log` เลือก "Accounts in this organizational directory only"
3. Redirect URI เลือกชนิด **Single-page application (SPA)** ใส่ `https://<project-id>.web.app/redirect.html` (ถ้าจะลองในเครื่อง เพิ่ม `http://localhost:5173/redirect.html` ด้วย) แล้วกด Register
4. API permissions > Add a permission > Microsoft Graph > Delegated permissions > `Calendars.Read` แล้วกด Add (ถ้าบริษัทไม่ให้ผู้ใช้อนุมัติเอง กด Grant admin consent)
5. หน้า Overview คัดลอก Application (client) ID และ Directory (tenant) ID (ไม่ต้องสร้าง client secret)

### 9.2 ใส่ค่าในระบบ

1. แก้ `public/ms-config.js` ใส่ค่าสองตัว (ไม่ใช่ความลับ)
   ```js
   export const msConfig = { clientId: '...', tenantId: '...' };
   ```
2. deploy เว็บ (ข้อ 11)
3. ผู้ใช้แต่ละคนไปที่ ตั้งค่า > เชื่อมต่อ Outlook / Teams แล้วล็อกอิน Microsoft

### 9.3 ไฟล์ที่เกี่ยวข้อง

- `public/redirect.html` หน้าเปล่าสำหรับรับผลล็อกอินในหน้าต่าง popup
- ในหน้าต่างปฏิทิน: นัดหมายแสดงเป็นแถบลายเฉียง (ม่วงคือ Teams น้ำเงินคือ Outlook) คลิกเพื่อนำเข้าเป็นงานหรือเปิดลิงก์ประชุม
- ปุ่ม Outlook บนแถบเครื่องมือเปิดหน้าต่างเทียบและนำเข้าทั้งช่วงที่เห็น
- โทเคนเก็บในเบราว์เซอร์และถูกล้างทุกครั้งที่ออกจากระบบ
- ลองหน้าตาโดยไม่ต้องมีบัญชีจริงได้ที่ `http://localhost:5173/?msmock` (ข้อมูลตัวอย่าง ใช้ได้เฉพาะ localhost)
- เครือข่ายบริษัทต้องอนุญาต `login.microsoftonline.com`, `graph.microsoft.com`, `cdn.jsdelivr.net`

## 10. สร้างแอป Windows (.exe)

แอปคือหน้าต่าง Electron ที่เปิดเว็บจริง จึงแก้เว็บแล้วแอปได้ของใหม่ทันทีโดยไม่ต้องแจกไฟล์ใหม่

1. เข้าโฟลเดอร์ `desktop`
   ```bash
   cd desktop
   ```
2. ติดตั้งเครื่องมือ (npm เวอร์ชันใหม่ข้ามขั้นตอนดาวน์โหลดตัว Electron ต้องรันเองต่อ)
   ```bash
   npm install
   node node_modules/electron/install.js
   ```
3. ที่อยู่เว็บอยู่ในค่าคงที่ `APP_URL` ของ `desktop/main.js` แก้ให้ตรงกับเว็บของคุณ
4. ทดสอบก่อน build ให้เห็นหน้าต่างเปิดเว็บ
   ```bash
   npm start
   ```
5. สร้างไฟล์ .exe
   ```bash
   npm run build
   ```
   ได้ไฟล์เดียวที่ `desktop/dist/DailyLog-1.0.0.exe` ประมาณ 105 MB ดับเบิลคลิกใช้ได้เลย ไม่ต้องติดตั้ง ไม่ต้องมีสิทธิ์แอดมิน เปิดครั้งแรกช้าประมาณครึ่งนาทีเพราะแตกไฟล์
6. สิ่งที่ `main.js` ทำนอกเหนือจากเปิดเว็บ
   - ตัดคำว่า Electron ออกจากข้อมูลที่ส่งให้เว็บ เพื่อให้หน้าล็อกอิน Microsoft ปฏิบัติเหมือนเบราว์เซอร์ทั่วไป
   - อนุญาตเปิดหน้าต่างเล็กเฉพาะหน้าล็อกอิน Microsoft ส่วนลิงก์ภายนอกไปเปิดในเบราว์เซอร์ปกติ
   - ไม่มีเน็ตให้แสดง `offline.html` และลองใหม่เองเมื่อกลับมาออนไลน์
   - ล็อกให้เปิดได้ทีละหนึ่งหน้าต่าง ปฏิเสธสิทธิ์กล้อง ไมค์ ตำแหน่ง
   - ทางลัด: F5 หรือ Ctrl+R โหลดใหม่, F11 เต็มจอ, Ctrl กับ + - 0 ซูม
7. ไอคอน: `desktop/icon.ico` (หลายขนาดสูงสุด 256 พิกเซล) และ `icon.png`
8. ไฟล์ยังไม่ได้ลงลายเซ็นดิจิทัล เครื่องใหม่จะขึ้น "Windows protected your PC" ให้กด More info แล้ว Run anyway การลงลายเซ็นต้องซื้อใบรับรอง
9. ไฟล์ .exe ไม่ขึ้น GitHub (ใหญ่เกินขีดจำกัด 100 MB) ถ้าจะแจก ให้ใช้ GitHub Releases หรือโฟลเดอร์แชร์

## 11. Deploy และตรวจหลัง deploy

ลำดับที่ปลอดภัยคือกฎก่อนเว็บเสมอ

```bash
npx firebase-tools deploy --only firestore:rules
npx firebase-tools deploy --only hosting
```

ตรวจหลัง deploy

1. เปิดเว็บ ต้องเห็นหน้า Login (หรือหน้าติดตั้งที่ `/#setup` ถ้ายังไม่เคยติดตั้ง)
2. ตรวจว่าคนนอกอ่านข้อมูลไม่ได้ ต้องได้ 403 ทั้งสองบรรทัด
   ```bash
   curl -s -o /dev/null -w "%{http_code}\n" "https://firestore.googleapis.com/v1/projects/<project-id>/databases/(default)/documents/events"
   curl -s -o /dev/null -w "%{http_code}\n" "https://firestore.googleapis.com/v1/projects/<project-id>/databases/(default)/documents/users"
   ```
3. ถ้าเบราว์เซอร์ยังแสดงของเก่า ให้โหลดซ้ำแบบล้างแคช (Ctrl+Shift+R) หรือต่อท้าย `?v=2`
4. ถ้ากฎเพิ่ง deploy แล้วขึ้นสิทธิ์ไม่พอ รอ 5 ถึง 30 วินาทีให้กฎกระจายแล้วลองใหม่

## 12. ขึ้น GitHub

1. ตรวจ `.gitignore` ให้ครบ ห้ามขึ้น repo: `node_modules/`, `desktop/dist/`, `.firebase/`, `.claude/`, ไฟล์ข้อมูลงานจริง (`Daily_Work_Log*.xlsx`), ไฟล์ log และโทเคนของเครื่องมือ
2. ตรวจว่าไม่มีความลับติดไป เช่น รหัสติดตั้ง โทเคน หรือรหัสผ่าน
   ```bash
   git grep -n -i -E "setupKey|secret|token|password" -- . ":!docs" ":!tests"
   ```
   ค่า `apiKey` ใน `firebase-config.js` เป็นค่าสาธารณะของเว็บแอปตามออกแบบ GitHub อาจแจ้งเตือนว่าพบคีย์ ให้ตรวจว่าตั้งข้อจำกัดคีย์ใน Google Cloud Console แล้ว
3. สร้าง repo และ push (แนะนำให้เป็น private)
   ```bash
   git init -b main
   git add .
   git commit -m "Daily Log: ปฏิทินงาน ล็อกอิน รายงาน Outlook/Teams และแอป Windows"
   gh auth login
   gh repo create daily-log --private --source . --remote origin --push
   ```
4. ครั้งต่อไป หลังแก้งาน
   ```bash
   git add -A
   git commit -m "อธิบายสิ่งที่แก้"
   git push
   ```

## 13. ปัญหาที่เคยเจอและวิธีแก้

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| สร้างฐานข้อมูลแล้วขึ้น 403 | Firestore API ยังไม่เปิด | รัน `deploy --only firestore:rules` จะเปิดให้เอง หรือสร้างใน Console |
| deploy กฎแล้วขึ้นสิทธิ์ไม่พอทันที | กฎยังกระจายไม่ทั่ว | รอ 5 ถึง 30 วินาที แล้วลองใหม่ |
| ผู้ใช้ล็อกอินได้แต่ไม่เห็นงานใดเลย | ผู้ใช้สิทธิ์ User ต้องกรองด้วย `ownerId` และงานเดิมยังไม่มีเจ้าของ | แอดมินกด "โอนให้ฉัน" ที่แถบด้านบน |
| กด "โอนให้ฉัน" แล้วไม่ผ่านทั้งหมด | มีงานเดิมอย่างน้อยหนึ่งงานข้อมูลผิดรูปแบบ (เวลาไม่ครบห้าตัวอักษร ฯลฯ) | แก้ข้อมูลของงานนั้น แล้วกดใหม่ การโอนเป็นชุดเดียวทั้งหมดหรือไม่ได้เลย |
| เปลี่ยนรหัสหรือเพิ่มผู้ใช้แล้วขึ้น "รหัสนี้มีคนใช้แล้ว" | รหัสต้องไม่ซ้ำทั้งระบบ | เลือกรหัสอื่น หรือกด "สุ่มรหัส" |
| ลืมรหัสแอดมินคนเดียว | ไม่มีทางกู้ในหน้าเว็บ | ใช้แอดมินสำรอง หรือแก้เอกสารใน Firebase Console |
| เชื่อม Outlook แล้วขึ้นว่าต้องให้ IT อนุมัติ | บริษัทไม่ให้ผู้ใช้อนุมัติแอปเอง | ให้ผู้ดูแลกด Grant admin consent ที่ API permissions |
| เชื่อม Outlook แล้วไม่มีหน้าต่างขึ้น | เบราว์เซอร์บล็อก popup | อนุญาต popup ของเว็บนี้ |
| ขึ้น redirect URI ไม่ตรง | URI ใน Entra ไม่ตรงกับ `/redirect.html` ของเว็บ | แก้ใน Entra ให้เป็นชนิด SPA และตรงทุกตัวอักษร |
| `npm install` ใน `desktop` แล้ว Electron เปิดไม่ได้ | npm ใหม่ข้ามสคริปต์ติดตั้งที่ดาวน์โหลดตัว Electron | รัน `node node_modules/electron/install.js` |
| Firestore emulator ไม่ยอมเริ่ม | ไม่มี Java | ติดตั้ง JDK 17 ขึ้นไป แล้วตั้ง `JAVA_HOME` |
| push ขึ้น GitHub ไม่ได้เพราะไฟล์ใหญ่ | มีโฟลเดอร์ `dist` หรือ `node_modules` ติดไป | เพิ่มใน `.gitignore` แล้ว `git rm -r --cached` โฟลเดอร์นั้น |
| เขียนไฟล์ภาษาไทยผ่าน heredoc ในเทอร์มินัลแล้วพัง | เทอร์มินัลบางตัวตีความอักขระพิเศษผิด | เขียนไฟล์ด้วยตัวแก้ไขข้อความแทน |

## 14. ข้อควรระวังด้านความปลอดภัย

1. **รหัส 6 หลักเดาง่าย** และเมื่อไม่มีชื่อผู้ใช้ ใครก็ลองสุ่มรหัสเพื่อหาว่ารหัสไหนมีเจ้าของได้ ความเสี่ยงสูงสุดคือสิทธิ์ที่เห็นงานทุกคน (Admin, Overview) ไม่ควรใช้เลขง่ายๆ เช่น 000111 ถ้าต้องการปลอดภัยขึ้น ให้เพิ่มความยาวรหัส หรือกลับไปใช้ชื่อผู้ใช้คู่กับรหัส หรือเพิ่ม reCAPTCHA / App Check
2. **สิทธิ์ทั้งหมดอยู่ที่ `firestore.rules`** แก้กฎแล้วต้องรันชุดทดสอบในข้อ 8 ซ้ำก่อน deploy
3. **อย่าใส่ความลับในโค้ดเว็บ** ทุกอย่างใน `public/` ใครก็เปิดดูได้ ค่า `apiKey`, `clientId`, `tenantId` ไม่ใช่ความลับ แต่รหัสติดตั้ง โทเคน และ client secret เป็นความลับ
4. **เครื่องที่ใช้ร่วมกัน** ให้กดออกจากระบบทุกครั้ง ระบบล้างโทเคน Outlook และไม่เก็บข้อมูลค้างในเครื่อง
5. **สำรองข้อมูลเป็นระยะ** ใช้ปุ่มสำรองในแถบข้าง หรือส่งออกจาก Firebase Console
